# 拆分边界与接入顺序

## 本轮决定

保留 JDK 21 和 Dropwizard/JDBI；先在一个 Java 进程内以 Maven 模块隔离术语库与上下文。接口层只依赖领域服务和 contracts；领域代码不引用平台存储实现或 OpenMetadata 全局 Entity 注册表。静态前端使用 OpenMetadata 的共享组件与明确列出的迁移组件，宿主路由和 API 调用独立。

直接复制原 Repository 会同时带入通用 EntityRepository、DAO 集合、用户/团队、审批、资产、搜索与 RDF 初始化。因此这里重写存储适配，并只承诺已有行为测试覆盖的提取范围。完整上游源码仍留在分支中，用于逐项对照。

## 已建立的替换位置

| 边界 | 当前实现 | 接入已有系统时 |
| --- | --- | --- |
| Caller 身份 | 配置令牌；回环开发身份 | JWT/SSO 映射稳定 user ID；可信团队/域主体 ID；填充读写范围 |
| EntityStore | JDBI + 独立 PostgreSQL 表 | 保留事务、乐观版本、级联和历史语义，可换为已有仓储 |
| BlobStore | 本地不可变 UUID 对象 | 对接 OSS/S3/文件服务，保留内容版本与失败回收 |
| AssetContextPort | 未配置时返回 501 | 调用已有资产 API，并在提供器内执行资产鉴权 |
| TagPolicy | 术语库互斥策略 | 同一策略供上下文实体复用；后续接已有资产标注接口 |
| 搜索更新 | 与实体写入同一事务的 sc_outbox | 增加按实体 ID/revision 幂等消费、重放和索引提供器 |
| 用户目录 | 只读配置身份投影 | 替换为已有用户/团队/域 API；不迁移用户主数据 |

当前 read 身份可读术语/文章/文档；写权限按 glossary/context scope 区分。Memory 另执行每条记录的 Owner、Private、Entity、Shared 与 Viewer/Editor 规则，并对历史快照再次检查。完整平台 RBAC、资产 ACL 和审批需要接入已有权限/工作流，不能仅把 scope 映射当成原平台全部策略。

## 当前容量与兼容边界

- 原型每种实体最多扫描 5,000 行，历史最多返回 5,000 版；超过时显式 503。写操作使用数据库事务锁保护整棵树和双向边，适合第一轮功能验证。扩展数据量前应增加数据库分页、权限条件下推与搜索适配，并把锁细化到聚合。
- 关联首轮只支持双向 `relatedTo`；审批、自定义关系、CSV、完整导入导出与资产标签联动尚未迁入。
- 文档提取当前为有边界的同步 UTF-8 文本处理；PDF/Office 和异步任务应通过独立提取适配实现，并保留内容版本检查。进程中断可能留下未引用 blob，正式对象存储接入应提供对账回收。
- Schema 与生成类型沿用 2.0.8，但新存储、`revision`、上传接口、宿主入口有差异；这不是原 OpenMetadata 的完整 API 替代品。V001 为新库幂等初始化脚本，后续结构升级需接入正式迁移工具。
- 语义搜索、自动提炼、向量索引、模型生成与 Persona 还未接入。当前的关键词 find、手工 Memory 和显式上下文组装均以真实存储为数据源。

## 下一步

1. 审核本轮可运行版本和接口边界，确定企业平台的用户、权限、资产和文件接口。
2. 先接真实身份与权限，再接 AssetContextPort 和对象存储；以现有系统作为主数据来源。
3. 按实际需要迁移原完整术语页、富文本文章/文档页面和用户/资产选择器；用适配层替换原全站提供器，逐页做契约回归。
4. 增加搜索 outbox 消费和语义检索；明确模型/Embedding 配置后迁移 AIContextFinder/Persona 的取数部分与缓存策略。
5. 迁移审批、扩展关系与导入导出，再讨论本体浏览器和独立 MCP 读取网关。
