# 第二轮源码裁剪

日期：2026-11-28。比较基线为本分支上一版 `6eca187238805bd1ef2bf9bc9a7e0fa082078e81`，不是上游完整仓库。

## 已实施

1. **仓储注册收窄**：`GovernanceContextProfile` 提供明确仓储集合；`Entity` 在构造仓储前过滤。`migrate` 单独初始化仍保留的历史迁移仓储，供原版迁移访问空资产表；不会注册对应 REST 资源，也不会放宽搜索索引集合。应用正常启动继续只注册允许的 46 类仓储。搜索映射复制后过滤为 20 类，避免修改共享映射加载器的原始内容。包括治理、上下文、Drive、用户团队及 MCP 所需索引。
2. **无关后端实现删除**：物理删除 145 个 Java 生产源码文件，包括 58 个 REST Resource、32 个仓储，以及不再被保留入口引用的 mapper、审计包等实现。原表字段批量打标签／术语分支随资产模块退出；AI 上下文不再读取表分析画像。保留术语及标签自身的关联逻辑。删除与已删除实现对应的测试，保留并运行公共权限测试。
3. **前端组件清理**：从应用入口和保留测试追踪静态、动态字面量导入与样式依赖，删除 295 个不可达生产代码文件及相应测试／样例。保留公共组件和测试所需代码；调整 7 个保留测试中失效的 mock。
4. **Schema 集合收窄**：根据剩余 Java／前端引用、运行时 Schema 路径、配置与安全契约、表单引用、`$ref` 和 Java 类型依赖闭包，删除 41 份 Schema（918 → 877），同时删除对应生成的 TypeScript 文件。Java 模型重新干净生成。三处内嵌类型显式声明原有 `javaType`，避免集合变化影响生成器的类名分配；JSON 字段形状不变。

MCP 的文件夹类型修正为原版实际名称 `folder`；修正 ingestion pipelines 的资源包路径判断。在关闭 pipeline client 的基线下，不再尝试初始化依赖该 client 的默认日志存储。原 SCIM、安全、审批、通知、Drive 和应用支持代码按依赖保留。

## 代码体量

前端口径在本表统一重新归类：Playwright 代码、测试、样例和测试辅助文件归入测试项，未计入生产代码，因此不能直接与此前回复的 482,641 行比较。删除量另包含测试／样例；本表不把删除测试当作生产代码缩减。cloc 默认的重复文件识别可能产生少量计数差异，因此生成代码和大项以约数呈现。

## 仍然保留的内容

- `EntityRepository`、搜索客户端、RDF、认证与 RBAC、工作流、事件、通用导入／引用／版本等共享底座。
- 某些资产仓储和模型仍被公共工具、搜索索引实现、迁移或保留测试引用，源码保留但不在默认产品中注册。索引配置原文件也保留共享内容，运行时仅加载允许的 20 类。
- 877 份 Schema 中仍有数据资产和连接配置模型；进一步大幅缩减需继续改造共享代码，不能仅按目录删除。
- 原根 POM、SDK、operator、Python ingestion 等目录尚未从仓库物理移除，但不属于本分发构建范围。IDEA 导入 `governance-context/pom.xml`。
- `full` 后端排查选项不能恢复已经物理删除的资源、仓储和页面。

保留原架构与原 UI 的前提下，这仍是数十万行共享实现的分发版。后续若要降到数万行，需要另行决定替换或改写哪些共享底座。

## 验证入口

在仓库根运行 `python3 governance-context/check-schema-refs.py`（Windows 可用 `py -3`）检查全部本地 Schema 文件与 JSON Pointer 引用，不需要数据库。Java 定向测试、运行包部署与实际 API／浏览器结果见 [VALIDATION.md](VALIDATION.md)。Windows / IDEA 的显式构建和启动步骤见 [WINDOWS-IDEA.md](WINDOWS-IDEA.md)。
